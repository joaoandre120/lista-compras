## 2. Regras de Git e Ambientes (GitHub + Codeberg)
- **Fluxo Duplicado:** Este projeto utiliza um fluxo de commits duplicado para o GitHub (`origin`) e para o Codeberg (`codeberg`). Sempre que sugerir comandos de Git para atualizar o repositório, lembre-me de enviar para ambos os remotos ou me dê os comandos específicos para essa estrutura.
- **Commits Atômicos:** Faça commits pequenos, focados e frequentes (um commit por tarefa resolvida), garantindo que modificações rastreadas recebam o devido `git add` antes do commit.
- **Conventional Commits:** Todas as mensagens de commit devem seguir rigorosamente o padrão *Conventional Commits* (`tipo: descrição curta`). Os prefixos obrigatórios para este projeto são:
    - `feat:` Para novas funcionalidades ou implementações inéditas.
    - `fix:` Para correções de bugs, erros de compilação ou incompatibilidade de dependências (Gradle/Kotlin).
    - `docs:` Para alterações exclusivas em documentações ou KDocs.
    - `style:` Para formatações de código que não alteram seu comportamento.

## 4. Estrutura de Telas (Jetpack Compose UI)
Sempre que criar ou sugerir modificações em arquivos de tela (ex: `XScreen.kt`), aplique rigorosamente o padrão de Separação de Estado e Interface (State Hoisting), dividindo o arquivo em três partes essenciais:
1. **Composable Principal (Screen):** É o ponto de entrada da tela. Deve receber o `ViewModel` (e opcionalmente um `Modifier`), coletar os estados e gerenciar os eventos (UI Actions), repassando-os para o conteúdo.
2. **Composable de Conteúdo (ScreenContent):** É uma função *stateless* (sem estado integrado) que recebe apenas os dados puros (estados) e os callbacks de eventos. Ela é a responsável real por renderizar o layout da tela.
3. **Preview Composable:** Um `@Preview` estruturado que consome diretamente o `XScreenContent`, injetando dados estáticos/fakes para visualização em tempo de design no Android Studio.
